You are working in a folder that contains the source of Caravanserai, a small
container orchestrator written in Go (module NYCU-SDC/caravanserai): a server
(cara-server) that schedules Projects (groups of containers) onto Nodes, a
per-node agent (cara-agent) that runs them with Docker, and a PostgreSQL store.

The system is meant to uphold these safety rules:

R1 Release authorization: an assignment on a lost Node may be released only
   when the release conditions hold (grace-expired release enabled, overlap
   allowed, and Managed volumes have a usable backup, or other valid evidence).
   Otherwise the assignment is kept and TakeoverRequired is set. A legal
   release records its reason and the cleanup it obliges.
R2 Assignment fencing: a write from an old assignment (UID, nodeRef or
   assignment generation does not match the current one) must be rejected.
R3 WorkloadStopped: once a workload is reported stopped for an assignment, that
   same assignment must not start it again, even after the agent restarts. A
   new assignment may start it.
R4 Local recovery budget: the agent restarts a failed Project at most 3 times;
   attempts that did not actually run do not count; it declares exhaustion only
   after the last attempt's verification deadline.
R5 Termination timeout: a Terminating Project on a lost Node is not marked
   TerminationBlocked before the timeout; after it, it is reported, never
   deleted outright.
R6 Lost-node clock: if a Node recovers and is lost again, the grace clock starts
   over; it must not reuse the earlier incident's clock.
R7 Concurrent updates: conflicting status writes are retried; a write must
   never silently discard another writer's committed change.
R8 Unknown ownership: when the agent cannot find out which Projects it owns, it
   must not stop or delete containers.
R9 Cleanup evidence: deletion completes only after ResourcesRemoved is
   confirmed for the assignment.
